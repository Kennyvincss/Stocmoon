# StocMoon — Architecture

StocMoon is a set of binary prediction markets on Base, priced by an onchain AMM and settled on
Chainlink's reference prices for Coinbase tokenized stocks (B20). Collateral is USDC.

## Components

| Component | Responsibility | Source of truth |
| --- | --- | --- |
| `contracts/src/StocMoonMarkets.sol` | Market creation, YES/NO ERC-1155 shares, FPMM buy/sell, liquidity, settlement, redemption, fees, pause, eligibility | **Chain** |
| `contracts/src/OracleAdapter.sol` | Asset registry (token address → feed), staleness, settlement round proofs | **Chain** |
| `contracts/src/MirrorAggregator.sol` | Testnet-only AggregatorV3 mirror of a mainnet feed, written by a relayer | Chain (trusted relayer, auditable) |
| `web/` | UI + API routes (stocks, prices, markets, portfolio, leaderboard, eligibility) | Reads chain + DB + Coinbase API |
| `services/indexer` | Reads contract events → `markets`, `positions`, `transactions`, `market_events` | Derived from chain |
| `services/keeper` | Creates rolling markets inside feed sessions, resolves expired markets with round proofs | Calls contracts (keeper key) |
| `services/relayer` | Testnet: copy mainnet Chainlink rounds to `MirrorAggregator`s | Mainnet feeds |
| `services/snapshotter` | Paginates the Coinbase API, stores `stocks` + `price_snapshots` | Coinbase API |

The browser never sends prices or settlement results to anyone. Prices shown in the UI come from the
API (`nav_price`) or from the feed via RPC; settlement happens only in contracts.

## Asset identity

An asset is identified by its **B20 token contract address on Base mainnet** (from the API's
`contract_address`), never by ticker. The same address is the asset key on testnet, where the feed is
a mirror. `config/assets.<network>.json` is generated by `pnpm assets:sync`, which pages through the
API, matches the configured feed proxies, and verifies each feed onchain (decimals, description,
answer > 0, freshness).

## Tradability rules (all must hold)

1. API record has a `contract_address` and a `nav_price` with `nav_price_updated_at`.
2. `paused_features` is empty (any pause ⇒ not tradable; shown as "Paused by issuer").
3. Asset is registered and enabled in `OracleAdapter` with a feed.
4. Feed answer > 0 and `now − updatedAt ≤ maxStaleness`.
5. User passes the jurisdiction/eligibility gate.

If the API is down we serve the last cached copy with a **stale** banner and the cache timestamp;
no synthetic numbers are produced.

## Market engine

One hub contract holds all markets (one USDC approval for everything, simple indexing).

```
struct Market (selected fields)
  kind            UP_DOWN | BATTLE | EVENT
  assetA/feedA    stock + feed snapshot (BATTLE also assetB/feedB)
  openPriceA/B    feed answer at creation (+ round id)
  openTime, tradingEndsAt, closeTime
  maxStaleness, settlementDelay, resolutionWindow, disputeWindow   ← snapshotted, immutable
  lpFeeBps, protocolFeeBps                                          ← snapshotted, immutable
  poolYes, poolNo, totalLpShares, collateral
  status          OPEN | PROPOSED | RESOLVED
  outcome         NONE | YES | NO | PUSH | INVALID
```

- Token ids: `marketId*2` = YES (UP / asset A wins), `marketId*2+1` = NO (DOWN / asset B wins).
- 1 share = 1e6 units = redeems for 1 USDC if it wins. Every share is backed 1:1 by USDC
  (`collateral == supply(YES)+poolYes == supply(NO)+poolNo`, tested as an invariant).
- Market creation: `MARKET_CREATOR_ROLE` (keeper), or anyone if `openCreation` is enabled. Creator
  must seed ≥ `minInitialLiquidity`. Duration must be allowlisted. Asset must be enabled, unpaused,
  fresh.

### AMM (FPMM)

Constant product over the pool's outcome balances `y · n = k`.

- **Buy** outcome with `x` USDC: fee `f` is taken, `x' = x(1−f)` mints `x'` complete sets into the pool,
  pool returns `y + x' − ⌈y·n/(n+x')⌉` YES shares. Requires `≥ minSharesOut` and `deadline`.
- **Sell** `s` shares: pool burns `c` complete sets where `(y+s−c)(n−c) = y·n`
  ⇒ `c = ((y+s+n) − √((y+s+n)² − 4sn)) / 2` (sqrt rounded up ⇒ pool-favouring), user gets `c(1−f)`,
  requires `≥ minUsdcOut`. This is the early-exit / **close position** path.
- Marginal price `P(YES) = n/(y+n)`. Quotes are indicative; execution is bounded by min-out.
- **Liquidity**: add `a` USDC ⇒ mints `a` sets; pool keeps them in the current ratio, the excess
  outcome shares go to the LP (Gnosis behaviour), LP shares `a·T/max(y,n)`. Remove: proportional
  pool shares; matched pairs are merged back to USDC automatically; after resolution they are
  redeemed. Withdrawal is always allowed (it is proportional and cannot hurt other LPs).
- **Fees**: `lpFeeBps` accrues to LPs (per-share accumulator), `protocolFeeBps` to the treasury.
  Hard cap 5% total. Shown before confirmation.

### Settlement methodology

Price = Chainlink Total Return Value answer (per token, multiplier included), in the feed's decimals.

1. **Opening price** — `latestRoundData()` at creation; requires `answer > 0` and
   `block.timestamp − updatedAt ≤ maxStaleness`.
2. **Closing price** — the round **in effect at `closeTime`**: the resolver submits `roundId` and
   `nextRoundId`. The contract checks `updatedAt(round) ≤ closeTime`, and either the successor
   round has `updatedAt > closeTime` (successor = `roundId+1`, or first round of next phase if
   `roundId+1` does not exist), or `round` is the latest round. Also `closeTime − updatedAt ≤ maxStaleness`.
3. Resolution is permissionless and allowed from `closeTime + settlementDelay` (gives relayers /
   oracle time to publish the round that covers `closeTime`).
4. **UP/DOWN**: `close > open` ⇒ YES (UP); `close < open` ⇒ NO (DOWN); `close == open` ⇒ **PUSH**.
5. **BATTLE (A vs B)**: compare percentage returns exactly via cross-multiplication
   `closeA·openB` vs `closeB·openA`. Higher ⇒ winner; equal ⇒ PUSH.
6. **Fallback**: if no valid close price can be proved by `closeTime + resolutionWindow`
   (stale feed, corporate action pause, weekend), anyone calls `resolveInvalid` ⇒ INVALID.
7. **Payouts**: winner share = 1 USDC, loser = 0; PUSH / INVALID: every YES and NO share = 0.50 USDC.
8. **EVENT (earnings)**: question, settlement source and rules are fixed in the creation event
   (hash stored). `RESOLVER_ROLE` proposes YES/NO/INVALID with an evidence URI after `closeTime`;
   during `disputeWindow` the `GUARDIAN_ROLE` may reject the proposal (emitted with reason); afterwards
   anyone finalizes.
9. **Emergency**: `GUARDIAN_ROLE` can pause new risk (create/buy/sell/addLiquidity/resolve). Exits —
   merge, remove liquidity, redeem — are never blocked. `emergencyInvalidate` (guardian, unresolved
   markets only) is evented with a reason. No role can modify an existing market's parameters.

## Compliance gate

- Server: middleware reads geo headers (`x-vercel-ip-country`, `cf-ipcountry`) and `BLOCKED_COUNTRIES`
  (default `US` + comprehensively sanctioned jurisdictions). Blocked visitors can read, cannot trade.
- User attestation: wallet signs a message (not a transaction); server verifies the signature and
  country, stores it, and — when `ELIGIBILITY_REQUIRED=true` onchain — the eligibility signer
  marks the address eligible in the contract (`ELIGIBILITY_ROLE`). Buy / add-liquidity / create
  check eligibility; exits never do.
- Contracts are public: someone can bypass the website. The onchain eligibility switch exists so a
  production deployment can enforce the gate at the contract level.

## Data model (PostgreSQL)

`users, user_preferences, stocks, price_snapshots, markets, market_outcomes, positions, transactions,
liquidity_pools, market_events, leaderboard_records, earnings_events, stock_battles, eligibility_attestations,
indexer_state`. See `db/migrations/0001_init.sql`. Every chain-derived row stores `(tx_hash, log_index)`
with a unique constraint, which makes the indexer idempotent (no duplicate processing).

## Leaderboard rules

Ranked only on **realised** results from resolved markets: realised P&L = sells + redemptions − buys per
(user, market). Accuracy = winning resolved markets / resolved markets with a directional position
(PUSH/INVALID excluded). Minimum 3 resolved markets and 10 USDC volume to rank. LP activity is excluded.
Unrealised values are shown separately and labelled "estimated".
